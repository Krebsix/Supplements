# Spike: PDF-Textextraktion in React Native

Ausgefuehrt 2026-08-13. Gehoert zu Task 1 aus
`docs/superpowers/plans/2026-08-12-laborbefund-einlesen.md`.

**Frage:** Laesst sich der Text eines Labor-PDFs in React Native lesen, ohne
ein natives Modul und damit ohne Development Build?

**Stand:** Drei von vier Huerden genommen. Der Laufzeittest auf dem Geraet
steht noch aus.

## Ergebnisse

### 1. Textextraktion in Node — funktioniert

`pdfjs-dist@4`, `legacy/build/pdf.mjs`, `getDocument({ data, useWorkerFetch:
false, isEvalSupported: false })`. Liest das Test-PDF vollstaendig.

### 2. Fehlende Browser-Funktionen — kein Hindernis

Geprueft, indem die Globals entfernt und die Extraktion wiederholt wurde:

| Funktion | Fuer Textextraktion noetig? |
|---|---|
| `DOMMatrix` | nein |
| `Path2D` | nein |
| `OffscreenCanvas` | nein |
| `Promise.withResolvers` | nein |

Sie werden nur beim Rendern gebraucht. Das Lesen kommt ohne aus, obwohl
`pdfjs` sie an 31 beziehungsweise 8 Stellen erwaehnt.

### 3. Metro-Bundling — nur mit Babel-Flag

Erster Versuch scheiterte:

```
`import.meta` is not supported in Hermes.
Enable the polyfill `unstable_transformImportMeta` in babel-preset-expo.
```

Behoben durch eine neue `babel.config.js`:

```js
module.exports = function (api) {
  api.cache(true);
  return {
    presets: [['babel-preset-expo', { unstable_transformImportMeta: true }]],
  };
};
```

Danach baut das Bundle durch. **Kosten: rund 1,2 MB** (9,4 MB auf 10,65 MB).

### 4. Laufzeit auf dem Geraet — offen

Bundling beweist nicht, dass `getDocument()` unter Hermes auch laeuft. Ein
Testknopf ist dafuer voruebergehend in `app/(tabs)/(more)/lab.jsx`
eingebaut; er waehlt eine PDF, extrahiert und zeigt das Ergebnis.

## Der wichtigste Fund

`getTextContent()` liefert Textstuecke **ohne jede Zeilenstruktur**. Wer sie
aneinanderhaengt, bekommt den ganzen Befund als eine Zeile:

```
"Laborbefund   vom   05.08.2026  Ferritin   45   ng/ml   30   -   300 25-OH-Vitamin   D   18,4 ..."
```

Ein zeilenweise arbeitender Parser findet darin nichts. Der Plan hatte
angenommen, die Extraktion liefere fertige Zeilen — sie tut es nicht.

Die Zeilen lassen sich aus den Positionsdaten rekonstruieren: `transform[5]`
ist die y-Koordinate (gleiche y heisst gleiche Zeile), `transform[4]` die x
(Reihenfolge innerhalb der Zeile). Damit:

```
Laborbefund vom 05.08.2026
Ferritin 45 ng/ml 30 - 300
25-OH-Vitamin D 18,4 ng/ml 30 - 70
TSH 2,1 mU/l 0,4 - 4,0
```

**Folge fuer den Plan:** Task 4 (`LabReportText.js`) muss diese
Rekonstruktion enthalten. Sie ist in `SpikePdfImport.js` bereits
geschrieben und kann uebernommen werden.

## Nebenbefund: die Parser-Regex trifft

Der regulaere Ausdruck aus Task 3 wurde gegen den rekonstruierten Text
geprueft, bevor der Parser existiert:

| Zeile | Ergebnis |
|---|---|
| `Laborbefund vom 05.08.2026` | korrekt ignoriert |
| `Ferritin 45 ng/ml 30 - 300` | Ferritin / 45 / ng/ml / 30 - 300 |
| `25-OH-Vitamin D 18,4 ng/ml 30 - 70` | 25-OH-Vitamin D / 18,4 / ng/ml / 30 - 70 |
| `TSH 2,1 mU/l 0,4 - 4,0` | TSH / 2,1 / mU/l / 0,4 - 4,0 |

## Offene Punkte

- **Laufzeittest auf dem Geraet.** Entscheidet endgueltig.
- **Bundle-Groesse.** 1,2 MB fuer eine Funktion, die nicht jede Nutzerin
  braucht. Falls das stoert, laesst sich `pdfjs` per dynamischem `import()`
  erst beim Oeffnen des Import-Screens laden; im Spike-Code ist der Import
  bereits dynamisch.
- **Echte Labor-PDFs.** Das Test-PDF ist selbst erzeugt und sauber gesetzt.
  Ob Befunde echter Labore mit ihren Tabellenrahmen ebenso sauber
  rekonstruiert werden, zeigt erst der Test mit einem echten Dokument.
- **Dependency-Pruefung.** `pdfjs-dist` ist noch nicht freigegeben; vor der
  dauerhaften Aufnahme gehoert sie geprueft (Hinweis der Endor-Integration).

## Vorlaeufige Empfehlung

Weitermachen mit `pdfjs-dist`. Bestaetigt der Laufzeittest das Bild, bleibt
das Feature in Expo Go testbar und braucht keinen Development Build.
Scheitert er, faellt der PDF-Weg auf ein natives Modul zurueck — dann
zusammen mit der Fotoerkennung, die ihn ohnehin braucht.
